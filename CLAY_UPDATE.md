## 1. Background — what is being changed and why

`clay-rs/` is a **plain vendored copy** of `github.com/clay-ui-rs/clay`. It is **not** a git subtree and
**not** a submodule — there is no `.gitmodules` and no `git-subtree-dir` trailer anywhere in history. It
was added at `2a10b81d` ("Gui: Vendor clay-rs minimally") and 9 commits have modified it since.

It is pinned at a **Clay 0.13-era** header. Upstream is on **0.14**.

Verified provenance (established by comparing git blob hashes, so these are facts, not guesses):

## 5. Phase D — migrate `zebra-gui` to 0.14 element-id semantics

**This is the hard phase. Read all of it before editing anything.**

### D-context: what 0.14 broke

0.14 moved element-id assignment from *configure* time to *open* time:

- `Clay_ElementDeclaration` **lost its `id` field**. (It is the only struct zebra-gui builds that changed
  shape — the other ~14, including `Clay_String`, `Clay_LayoutConfig`, `Clay_Sizing`, `Clay_Padding`,
  `Clay_Color`, `Clay_ClipElementConfig`, `Clay_FloatingElementConfig`, are field-identical.)
- `Clay__HashString` changed arity: `(key, offset, seed)` → `(key, seed)`. The old 3-argument form is now
  called `Clay__HashStringWithOffset`. Both are `CLAY_DLL_EXPORT`, so bindgen emits both.
- `Clay__AttachId` was **deleted**, and `Clay__AddHashMapItem` lost its `idAlias` parameter. Re-iding an
  already-open element is therefore impossible.
- `Clay__OpenElement()` now **eagerly generates an anonymous id** via `Clay__GenerateIdForAnonymousElement`.
  `Clay__OpenElementWithId(Clay_ElementId)` is the id-supplying form, and it is `CLAY_DLL_EXPORT`.

### D-trap 1: the ordering problem (read twice)

`Clay__GetParentElementId()` is implemented as `openLayoutElementStack[length - 2]`
(upstream `c7fadc915144` `clay.h:1324`; byte-identical to our 0.13 header).

- **Today:** `elem()` opens the element first, *then* `id("Main")` is evaluated inside the `Decl` literal.
  So the stack is `[…, parent, self]` and `[length-2]` is the **true parent**. Correct.
- **Naively ported:** `elem(id("Main"))` evaluates the id *before* the open. The stack is
  `[…, grandparent, parent]` and `[length-2]` is the **grandparent**. Every id silently changes value and
  siblings under different parents start colliding.

`Clay__GetOpenLayoutElement()` would return the right thing, but it has no `CLAY_DLL_EXPORT` prototype in
the public header section (it is only defined mid-file), so bindgen does not export it — and exporting it
is a divergence we decided not to take.

**The compiler cannot catch this. Do not improvise.**

### D-fix: a parent-id stack owned by `ui.rs`

`ui.rs` already owns `elem()` / `elem_bgn()` / `elem_end()` / `Element::drop`, so the stack lives there and
costs no divergence from upstream. Because the stack top is the parent's real id, this reproduces today's
`Clay__GetParentElementId()` value **exactly** — provided every opened element has a Rust-known id.

Sketch (adapt to local style; do not copy blindly):
```rust
thread_local! {
    static PARENT_IDS: std::cell::RefCell<Vec<u32>> = const { std::cell::RefCell::new(Vec::new()) };
}

pub fn parent_id() -> u32 {
    PARENT_IDS.with(|s| *s.borrow().last().expect("parent id stack not seeded"))
}

// Call once immediately after Clay_BeginLayout, before any elem().
pub fn parent_ids_seed() {
    let root = unsafe { clay::Clay__HashString("Clay__RootContainer".into(), 0) };
    PARENT_IDS.with(|s| { let mut s = s.borrow_mut(); s.clear(); s.push(root.id); });
}
```
`"Clay__RootContainer"` with seed `0` is the exact value 0.14 itself uses for the root — `Clay_BeginLayout`
opens it with `Clay__OpenElementWithId(CLAY_ID("Clay__RootContainer"))`. Seeding with it keeps top-level
ids at their current values.

Then:
- `elem_bgn(id)` → `unsafe { clay::Clay__OpenElementWithId(id.clay()) }`, then push `id.id`.
- `elem_end()` → pop, then `unsafe { clay::Clay__CloseElement() }`.
- `elem(id)` → `elem_bgn(id); Element { id, ..Default::default() }`.

### D-steps

- [ ] **D1.** In the `id()` and `id_index()` helpers, replace
  `clay::Clay__HashString(label.into(), N, clay::Clay__GetParentElementId())` with
  `clay::Clay__HashStringWithOffset(label.into(), N, parent_id())`.
  **Both changes are required together:** the function rename *and* the switch from
  `Clay__GetParentElementId()` to `parent_id()`.
- [ ] **D2.** Add the thread-local stack, `parent_id()` and `parent_ids_seed()` beside `elem()`.
- [ ] **D3.** Rewrite the `elem()` / `elem_bgn()` / `elem_end()` trio per the sketch above.
- [ ] **D4.** Call `parent_ids_seed()` immediately after layout begins, right after the
  `clay.begin::<(), ()>()` / `Clay_SetCurrentContext` pair.
- [ ] **D5.** Remove the `id: Clay_ElementId_ZERO,` field from `Clay_ElementDeclaration_ZERO`.
  `Clay_ElementId_ZERO` may become unused; delete it if so.
- [ ] **D6.** Delete `decl.id = item.id.clay().id;` from the free `pub fn decl(item: Decl)` entirely.

- [ ] **D7.** **Move the id off `Decl` and onto `Element`.** One field moves, but it has readers.
  - Remove `id: Id,` from `pub struct Decl`, and from the `pub const Decl: Decl = Decl { … }` default.
  - `pub struct Element` currently holds only `decl: Decl`. Give it an `id: Id`, set by `elem()` /
    `elem_bgn()`. `Element::decl` keeps storing the whole `Decl`; the `Decl` just no longer carries an id.
  - **Six sites read the id back out of the element** as `_elem.decl.id` or `el.decl.id`
    (`grep -n 'decl\.id' ui.rs`). Rewrite each to `_elem.id`. The compiler flags all of them
    (`no field 'id' on type 'Decl'`), so work by iteration.
  - **One site reads the id off a `Decl` *template variable*:**
    `id_index("finalizer bar inner", final_decl.id.id)`. `final_decl` is built with `..Decl` and never
    assigns `id`, so `final_decl.id.id` is **always 0**. Replace it with
    `id_index("finalizer bar inner", 0)` — behaviour-preserving. Do **not** "correct" it to the finalizer
    index: those siblings are already disambiguated by their distinct parents, and changing the offset
    would move ids for no reason.

- [ ] **D8.** Migrate the call sites.
  ```
  elem().decl(Decl { id: X, .. })   ->   elem(X).decl(Decl { .. })
  ```
  Measured on `dev`, 2026-09-11: **183 `elem()` calls** in `ui.rs`, of which roughly **96** pass an
  explicit `id:`. Treat those as a sanity check, not a worklist — after D5-D7 every site with an `id:`
  field is a hard error, so `pheck.bat zebra-gui` enumerates the exact set for you.
  **Do this by compiler-guided iteration, not by regex.**

- [ ] **D9.** The remaining **anonymous `elem()` sites** and the **six bare `elem_bgn();` sites**
  (`grep -n 'elem_bgn();' ui.rs`) must now supply an id. `Clay__OpenElement()` can no longer be used at
  all, because the anonymous id it generates internally is unknowable from Rust and would desync the
  stack. Give each a stable explicit label, or a derived `id_index("anon", counter)` where the counter is
  deterministic frame to frame.

  **D-trap 2 — `Decl` template variables spread across several anonymous siblings.** `group_decl` is
  spread into six `elem()` calls and `chip_decl` into three (`grep -n 'group_decl\|chip_decl' ui.rs`).
  Today those siblings are distinct *only* because `Clay__OpenElement()` invents a fresh anonymous id for
  each one. Hand them a single shared label and they become genuine duplicate ids under one parent — the
  exact crash `8e7ded5b Gui: Fix crashing on duplicate IDs` was about. Each needs its own label, or an
  `id_index(label, n)` with a distinct `n`. **The compiler cannot catch this either.** Expect more of this
  shape than the two named here; read every `..some_decl` spread you re-id.

  **Consequence to expect:** ids for children of the previously-anonymous elements change value. That is
  harmless — ids only need to be unique and stable across frames — but scroll positions keyed by those ids
  reset once, on first run. Do not treat that as a bug.

- [ ] **D10.** `pheck.bat zebra-gui` must now pass. Fix remaining errors; they will be mechanical.

## 8. Known risks

- **Phase D is the risk.** ~183 call sites plus two id traps the compiler cannot see. V2 covers trap 1;
  only reading every `..some_decl` spread covers trap 2.
- Phases A-C are mechanical and independently verifiable. Keeping D and E in their own commits lets a
  bisect separate "0.14 landed" from "ids migrated".
- `git subtree pull` will still conflict inside the `clay.h` patch regions whenever upstream edits the
  text-wrapping code — it did in two places this time. That is inherent to carrying the char-wrap feature
  and is why the `LOCAL:` markers matter. `.cargo/config.toml` is a second, quieter conflict surface.
- `#![allow(unsafe_code)]` has no visible `deny` driving it anywhere in the tree; it may be vestigial.
  Harmless until E2 removes it.
